# Phase 1 项目规约

## 1. 目标

本仓库交付“预测—协调—自治”的车路云一体化可执行原型。系统必须形成
SUMO、边缘端、云端、车端、指标、报告与可视化之间的闭环，不以静态页面、
随机指标或仅能导入的模块代替运行证据。

## 2. 不可违反的工程约束

1. 主办方原始文件只读，所有派生物写入本仓库并记录来源与哈希。
2. `official_20_independent` 是主办方 20 个独立路口复现集，不宣称其构成连续路网。
3. `xiongan_rongdong_20` 保留 demo14、15、17、18、19、20 六个位置锚点并从公开 OSM 选择 14 个直接相邻
   信号路口；新增路口参数标记为 `modeled_from_organizer_data`，不宣称实测。
4. 云端只能下发区域目标，任何 SUMO 信号动作必须由边缘端经安全内核执行。
5. 控制、事件和执行反馈不得因可视化背压而丢弃。
6. 所有消息携带版本、消息 ID、trace ID、序列号、实验 ID 和有效期。
7. 所有实验必须记录配置、种子、场景哈希、算法版本和代码版本。
8. 未实际运行的实验显示“尚未运行”，严禁制造性能数据。

## 3. 模块依赖

应用模块只依赖 `packages` 中的公共协议和接口。算法插件不得直接访问数据库、
MQTT、TraCI 或前端；SUMO 调用集中在适配器；跨模块运行通信使用 REST、MQTT
和 WebSocket。

## 4. 验证闸门

- 结构闸门：配置、JSON Schema、OpenAPI、场景 manifest 可校验。
- 运行闸门：SUMO 正常结束且需求完成情况单独报告。
- 闭环闸门：状态上报、策略下发、安全执行、反馈和指标链路完整。
- 故障闸门：断云、延迟、丢包、算法异常均产生事件与受控降级。
- 证据闸门：报告只引用本次实际运行产生的数据。

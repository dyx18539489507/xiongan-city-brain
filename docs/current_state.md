## 数据与真实性边界

仓库保留两套用途不同、不得混称的数据集：

1. `official_20_independent`：主办方 20 个独立路口的 Excel、PNG 和 SUMO 复现证据集。它用于参数依据、单路口复现和算法单测，不能描述为连通区域路网。
2. `xiongan_rongdong_20`：从完整容东 OSM 路网派生的区域级工程验证场景。底层完整 OSM 网络不裁剪、不物理拆成 20 路口子网，区域需求也不被强制限制在 20 个受控路口；K01—K08、B01—B12 只是稳定的控制与观测编号。

主办方原始资料和冻结的 `rongdong.control.net.xml` 保持只读。冻结网络 SHA-256 为
`608DBE931FEDF85F56F1E2C8B5F5973F19E9ADE77A0D136671A27439D786E367`，本轮增强前后未改变。
多主体能力构建在同一完整 OSM 的派生网络 `rongdong.multimodal.net.xml` 上，不覆盖冻结文件。

OSM 提供地理与标签证据；需求、功能区解释和 6+14 参数迁移属于可追溯工程建模，没有现场实测流量标定，也不称为运营级数字孪生。

## 本轮已经实现

### 参数与路口清单

- 六个保留锚点直接使用相应主办方 Excel 的流量、转向和配时依据。
- 新增 14 个 OSM 路口的捐赠池已排除全部六个锚点，明确为主办方其余路口 `[1..13, 16]`；采用 Gower 距离、逆距离平方加权、容量缩放、Dirichlet 平滑和图拉普拉斯平滑。
- K01—K08 为核心走廊，B01—B12 为背景控制点；OSM/SUMO 原始 ID 始终保留。
- `intersection_inventory.json/csv` 记录道路、方向、车道、转向、信号相位、参数来源、文件哈希和置信边界。

### 完整 OSM 多主体场景

- 派生网络保留完整容东 OSM 范围：7,077 条普通边、10,712 条车道；没有物理裁剪成独立子网。
- 具有 7,356 条可步行车道、3,288 条可骑行车道、1,689 处人行横道和 2,372 个 walking area。
- 同时建模自行车、电动自行车、成年人和老年行人；独立需求包含 160 辆自行车、210 辆电动自行车和 287 名行人。
- 行人信号采用条件并行：仅在 SUMO 网络确有可控制横道且冲突关系可验证时，与兼容机动车相位并行；没有横道证据的路口不伪造行人相位。当前 20 个观测路口中 11 个具备平面受控横道证据。
- 机动车增加出租车、网约车和配送车类型；功能区标签来自 OSM，保留原始 tag 和来源，不把工程假设写成现场事实。
- `multimodal.rou.xml` 与机动车区域 OD 共用完整网络；只有一部分路线专门覆盖连续控制走廊，其余路线可使用全网。

### 云边路侧车闭环

- 独立 `rsu-service` 从 SUMO 观测主题接收原始区域状态，校验后发布 RSU 状态；边缘端不再冒充独立路侧模块。
- 实际链路为 SUMO → RSU → edge → cloud → edge → safety kernel → TraCI/vehicle guidance → feedback/metrics。
- 消息工厂按服务、场景和实验保持持久序列，修复逐帧重建导致的乱序拒绝。
- 云端按走廊距离、目标速度、占有率和风险动态给出 60—120 s 周期与相位偏移；B3 将绿波窗口、云端权重、预测到达和下游剩余容量共同计入本地压力。
- 短时超时进入 `HOLD_LAST_VALID`，继而进入 `EDGE_AUTONOMOUS`；恢复后先 `RECOVERY_SYNC` 再平滑回到 `CLOUD_COORDINATED`。

### 多主体指标与存储

- TraCI 直接采集机动车、自行车、电动自行车和行人状态；轨迹批次带 `participant_kind`，行人也进入分级采样持久化。
- 指标区分机动车/骑行/行人数量、排队、等待和完成量；安全监视器按观测轨迹计算机动车—机动车、机动车—非机动车、机动车—行人的 TTC/PET 代理指标，不使用随机数伪造。
- TimescaleDB 2.29.1 已实际启用；`metrics`、`events`、`vehicle_trajectories` 均为 hypertable，并配置压缩和保留策略。
- 迁移前备份：`results/backups/pre-timescale-20260805-233907.dump`，SHA-256 为
  `1D19413583357AFAA71D4BFBCA2F94FCD5A3415B3CD480782E89DA5254519554`。

### 模型接口

- B0 固定配时、B1 感应控制、B2 最大压力、B3 云边协调最大压力均可运行。
- STGNN、MPC 和 MARL 已有正式 artifact/protocol/哈希/训练与验证门禁；没有合格模型文件时只返回 `MODEL_NOT_AVAILABLE`，当前没有训练模型和性能结论。

## 当前限制

- 20 个观测路口并非全部具有 OSM 平面横道证据；不能为了“20/20”而伪造横道、等待区或信号控制。
- TTC/PET 是基于 SUMO 轨迹和空间邻近的代理安全指标，不等同于真实冲突调查或 SSAM 现场校准。
- 动态绿波已进入策略和 B3 决策，但正式收益仍需完整 5 种子长时实验及置信区间。
- 完整 OSM 仍会带来较高 TraCI 开销；已把每秒多次全车辆读取合并为一次。最新 20 s 冒烟实时因子约 1.79—1.96，物理 Compose 60 s 为 0.789；优化前 1,800 s 运行因无结果被终止，这不能替代正式性能验收。
- 阿里云/本地拆分 Compose、TLS 和安全配置均可校验，但没有真实阿里云主机和公网凭据，不能声明云上部署验收完成。
- 未做、且按用户要求不做现场实测流量标定和运行级数字孪生。

## 完整性约束

1. 不修改主办方原始资料和冻结底层 SUMO 网络。
2. 不把独立 20 路口资料伪装成连通区域。
3. 不裁剪完整 OSM，也不把全网车辆和 OD 强制聚焦到 20 路口。
4. 不伪造横道、功能区、流量标定、算法提升或模型预测。
5. 所有参数迁移保留捐赠者、权重、公式、哈希和来源边界。
6. 所有信号动作必须经边缘安全内核；云端和 RSU 均不能绕过边缘直接切灯。

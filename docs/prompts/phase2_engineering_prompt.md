SUMO/历史实验数据

七、数据集工程
==================================================

建立真实数据集流水线，不允许直接在训练脚本里临时拼接数据。

输入来源：

- 主办方 Excel 派生的流量、转向和信号参数；
- SUMO 真实运行产生的车辆、车道、路口、信号、扰动和通信事件；
- OSM 路网拓扑及其哈希；
- 场景配置、随机种子、算法版本和仿真版本。

建议预测目标：

- 每个路口/进口道未来 30、60、120 秒的到达流量；
- 未来 30、60、120 秒的占有率或排队长度；
- 可派生的下游溢出风险概率或风险等级。

最小特征集：

- 历史到达率、排队、占有率、平均速度、放行率；
- 当前相位、相位剩余时间、周期位置；
- 上下游邻接和路段容量；
- 时段、场景、扰动、通信状态；
- 网联车辆渗透率和可观测比例；
- 可选天气等外部变量只能在存在真实来源时接入。

必须实现：

1. 固定时间窗口和采样间隔；
2. 缺失值、异常值、重复记录和时间回退检查；
3. 单位、范围、单调时间和拓扑 ID 校验；
4. 原始索引、处理后数据和训练切分分离；
5. Parquet 或等价列式存储；
6. 数据集 manifest、Schema、哈希、生成命令和环境信息；
7. Dataset Card，说明数据来源、用途、限制和不可推断内容；
8. 训练/验证/测试按 `scenario_id + seed + run_id` 分组切分；
9. 禁止同一次仿真的相邻窗口同时进入训练集和测试集造成泄漏；
10. 标准化器只在训练集拟合；
11. 数据生成可断点续跑，已完成分片不可被静默覆盖；
12. 每个数据分片可追溯到 SUMO 输出、场景哈希和 Git 修订。

输出数据质量报告，至少包括：

- 样本量和覆盖场景；
- 每个特征缺失率；
- 每个预测目标分布；
- 不同路口、时段和扰动的覆盖度；
- 训练/验证/测试是否存在重复 run_id；
- 数据漂移和极端值；
- 低置信度工程参数占比。

八、预测模型体系
==================================================

先实现并评估简单基线，再开发复杂模型：

P0 `PersistenceForecaster`

- 使用最近一个观测作为未来预测；
- 必须作为最低预测基线。

P1 `HistoricalMeanForecaster`

- 使用相同时段、相同路口的训练集历史均值；
- 不得读取测试集未来数据。

P2 `TabularTrafficForecaster`

- 使用 Ridge、Random Forest、HistGradientBoosting 或质量等价的轻量模型；
- 配置、特征和随机种子固定可复现。

P3 `LightweightSpatioTemporalForecaster`

- 使用真实路网邻接关系；
- 优先采用轻量图传播特征 + TCN/GRU，或小型时空图网络；
- 不要一开始使用参数规模过大的模型；
- 支持多步预测；
- 输出预测值、置信度/不确定性和模型版本；
- 模型结构必须能导出 ONNX；
- 没有可用模型时返回正式错误，不能随机输出。

模型评估至少包括：

- MAE；
- RMSE；
- WAPE；
- SMAPE；
- R²；
- 分路口误差；
- 分预测时距误差；
- 高峰、施工、事故、活动散场下误差；
- 对拥堵/溢出风险的 Precision、Recall、F1、PR-AUC；
- 推理延迟、模型大小、CPU 和内存。

MAPE 在真实值接近零时不得作为唯一结论。报告应同时给出绝对误差和加权误差。

必须实现：

- 统一 `TrafficForecastModel` Protocol；
- 配置校验；
- 训练、验证、测试和推理解耦；
- early stopping；
- 确定性随机种子；
- checkpoint 与最佳模型选择；
- 模型卡；
- ONNX 导出；
- ONNX 与原生模型数值一致性测试；
- 可选动态量化，并比较量化前后的精度、体积和延迟；
- 模型签名、SHA-256、语义版本和回滚；
- 模型加载失败、版本不兼容、NaN/Inf、超时和输出越界处理。

九、B4 预测驱动云边协调控制器
==================================================

将 Phase 1 的占位 B4 实现为正式算法：

`PredictiveCoordinatedController` / `P-CMP`。

设计原则：

1. 云端使用 P3 或当前激活预测模型计算未来到达量、下游占有率和溢出风险；
2. 云端输出区域协调目标，不直接切换 SUMO 信号灯；
3. 边缘端继续使用本地最大压力做秒级控制；
4. 综合压力应包含：当前进口排队、出口可用容量、预测到达量、预测溢出风险、云端疏散权重、相位切换代价；
5. 对下游高风险路段抑制上游释放；
6. 对瓶颈出口、应急车辆路径和恢复路段提高疏散权重；
7. 所有动作仍须经过安全内核；
8. 模型无效、过期、超时、置信度过低或输出异常时无缝退回 B3；
9. B4 异常不得使边缘端退出控制循环；
10. 预测模型恢复后必须先进入 shadow/recovery 状态，不能立即强制切相位。

建议新增原因码：

- `PREDICTED_ARRIVAL_SURGE`；
- `PREDICTED_DOWNSTREAM_SPILLBACK`；
- `LOW_FORECAST_CONFIDENCE`；
- `MODEL_TIMEOUT_FALLBACK_B3`；
- `MODEL_OUTPUT_INVALID`；
- `MODEL_VERSION_MISMATCH`；
- `EMERGENCY_CORRIDOR_PRIORITY`；
- `RECOVERY_SHADOW_MODE`。

新增模型运行状态：

- `MODEL_SHADOW`；
- `MODEL_ACTIVE`；
- `MODEL_DEGRADED`；
- `MODEL_UNAVAILABLE`；
- `MODEL_RECOVERY_VALIDATION`。

模型状态不得替代原有边缘通信降级状态机，两者需要正交组合并有测试覆盖。

==================================================
十、创新点的工程化表达
==================================================

项目创新点应围绕以下可验证机制展开：

1. 预测不是直接控制，而是生成带有效期和置信度的区域目标；
2. 边缘端保留秒级自治与安全最终裁决权；
3. 当前状态最大压力与未来到达/溢出风险联合优化；
4. 模型失效、通信失效和局部算法失效具有分级、可恢复降级；
5. 预测模型通过 ONNX 在受限 CPU 环境轻量运行；
6. 用同 OD、同种子、同扰动的配对试验证明每个机制的独立贡献；
7. 用拓扑和参数不确定性试验说明结论适用边界。

十二、轻量化推理与资源约束
==================================================

优先支持 ONNX Runtime CPU 推理。

至少测量：

- 模型文件大小；
- 参数量；
- 单样本和批量 P50/P95/P99 推理延迟；
- 峰值内存；
- CPU 使用率；
- 冷启动时间；
- 连续运行吞吐；
- 量化前后精度差异；
- 量化前后延迟和体积差异。

工程目标，不得伪造：

- ONNX 与原生模型最大绝对误差不超过配置阈值，默认 `1e-4`；
- 模型文件目标不超过 20 MB；
- 开发机 CPU 单次区域预测 P95 目标不超过 50 ms；
- 云端完整决策 P95 目标不超过 100 ms；
- 若未达到目标，必须记录真实结果、瓶颈和优化过程，不能篡改阈值掩盖失败。

如果没有 ARM 或车规硬件：

- 可以构建 `linux/arm64` 镜像并验证镜像可构建；
- 不得声称完成 ARM 实机性能验证；
- 报告必须显示 `ARM_RUNTIME_NOT_MEASURED`。

==================================================
十三、正式实验设计
==================================================

实验体系分三级：

### Level 1：PR/开发冒烟

- 20—60 秒；
- seed 11；
- B0、B3、B4；
- 验证代码、契约和报告链路，不用于性能结论。

### Level 2：夜间回归

- 至少 600 秒；
- seeds `[11, 23, 37]`；
- S01、S02、S04、S07；
- B0—B4；
- 用于发现回归和失败场景。

### Level 3：正式竞赛基准

核心矩阵：

- 算法：B0、B1、B2、B3、B4；
- 场景：S01、S02、S03、S04、S05、S07；
- 随机种子：`[11, 23, 37, 41, 59]`；
- 仿真时长：至少 3600 秒，或采用正式配置规定的观察期与清空期；
- 同一场景/种子必须复用完全相同的路网、OD 文件、车辆类型、发车时间、扰动和通信条件；
- 只改变算法；
- 目标 150 次核心实际运行。

附加敏感性矩阵：

1. 网联车辆渗透率：0%、20%、50%、80%、100%；
2. 通信条件：N0、N1、N3、N5、N8；
3. 参数候选：低/中/高需求与容量；
4. 拓扑候选：对低置信度路口采用合理候选，不改变官方证据部分；
5. 有/无速度引导；
6. 有/无预测项；
7. 有/无预测置信度门控；
8. 原生模型与量化 ONNX。

必须先冻结核心 OD 与扰动，再批量运行。禁止每个算法重新随机生成需求。

十四、统计与因果边界

至少输出：

- 每个算法的均值、中位数、标准差、IQR；
- B1—B4 相对 B0 的配对绝对差和相对差；
- B4 相对 B3 的配对差，用于隔离预测贡献；
- bootstrap 95% 置信区间；
- 最佳、典型和最差种子；
- 失败运行、超时运行和未清空运行占比；
- 分场景结果，不得只报告总体平均；
- 统计显著性与工程意义分开解释；
- 多指标下不得只挑选对算法有利的指标。

若模型或算法没有稳定优于基线：

1. 保留负面结果；
2. 分析误差来自预测、控制、通信还是场景容量；
3. 做机制消融和参数敏感性；
4. 继续优化可以修复的工程问题；
5. 不能把失败运行从汇总中静默删除。

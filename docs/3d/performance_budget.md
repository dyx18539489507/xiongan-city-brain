# Web 3D 性能预算

## 硬件上限与验收目标

正式上限为 i7-8565U、8 GB RAM、NVIDIA MX250 2 GB，在 1280×720 下争取稳定 25—30 FPS。FPS、GPU 和显存必须以 Phase 11 的实机运行记录为准；本文件中的预算不是实测结论。

## 当前强制预算

| 项目 | 当前约束 | 理由 |
|---|---:|---|
| WebGL 渲染 | `WebGLRenderer` | 比赛版本不要求 WebGPU |
| device pixel ratio | 最大 `1.25` | 防止高 DPI 屏无上限扩大像素量 |
| 渲染目标 | native/balanced/performance = 30/24/20 FPS | 常规场景争取 25–30；机非人总数达到 180 且持续慢帧时保留 CPU 余量 |
| 静态道路批对象 | 当前 13 个 | 车道按材质合批，横道/标线/路口分别合批 |
| 最终矩阵三角形峰值 | 196,653 | 包括静态环境、K06 按需建筑层、TLS 专用符号和当时动态实体；来源为当前 MX250 45 组合 |
| 实时阴影 | Phase 2 关闭 | 后续只给核心近景和重要对象分配预算 |
| 场景原始 JSON | 11,881,458 bytes | API gzip、浏览器缓存、分阶段构建 |
| 本机 gzip 传输抽查 | 1,266,646 bytes / curl 1.48 s | 单次本地 HTTP 抽查，不是完整首屏 benchmark |
| renderer far plane | 10 km | 覆盖场景，后续配合 LOD/裁剪 |
| 历史图表 | 后续环形缓冲 | 禁止无限增长 |

## 后续资源预算

- 纹理：默认 1K 或以下；核心少量 2K；禁止全域 4K。KTX2/Basis 优先，按场景释放。
- 静态环境：树木、路灯、护栏、锥桶和重复建筑组件必须实例化。
- 车辆：LOD0/1/2，共享 geometry/material；近景才允许轮胎、灯光和有限阴影。
- 人物：近景少量骨骼，中距低骨骼，远距极低面或 billboard；逻辑实体不能因降级而删除。
- 光照：一个主方向光、环境光/HDRI、有限阴影；不使用实时 GI、SSR 或大规模 PointLight。
- 后处理：默认色调映射与浏览器抗锯齿；Bloom/AO/SMAA 必须单独 benchmark 后启用。

## Phase 2 已观察风险

生产构建仍提示 Three.js `731.74 kB` 和 ECharts `511.34 kB` minified chunk 超过 500 kB。当前已独立分组；图表按需加载但 Three.js 是首屏核心依赖，这是后续首屏加载优化项，不能把“构建成功”误报成性能达标。

静态 scene 解码时仍会短暂同时存在网络响应字节、解码字符串和对象树。分阶段构建与 Replay inventory 缓存后，冷启动 probe 为 20.18 秒；当前矩阵 JS Heap 峰值 153.4 MB，最终代码长稳峰值 159.8 MB。若继续压缩首屏，应优先拆分静态 payload，而不是提高纹理或并发加载预算。
